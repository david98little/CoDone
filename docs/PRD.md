# 概要

CoDone 是一款嵌入微信聊天场景的轻量协同待办小程序，让用户把任务分享给好友或群成员，各自订阅提醒、共同完成。

## 二、背景与问题

### 2.1 背景

微信已经成为朋友、家人和小团队沟通的默认场景，但待办事项仍然散落在聊天、备忘录、日历和各类待办 App 中：

- 任务在聊天里说清楚后，缺少一个稳定的清单承接。
- 邀请好友协作要加好友、发链接、注册账号，路径长。
- 任务到期后靠人记、靠人催，容易漏掉。
- 现有待办工具偏向个人管理，微信里的协同关系没有被利用起来。

CoDone 的切入点是把“清单、任务、邀请、提醒”压缩进微信已有的聊天关系里，让用户不需要离开微信就能完成一次轻量协作。

### 2.2 核心问题

1. 如何让好友以最低成本加入同一份清单？
2. 如何让任务在聊天里被看见，而不是沉到聊天记录里？
3. 在微信订阅消息限制下，如何提供可接受的到期提醒？
4. 如何让“谁负责、谁完成、谁还没订阅”这些状态足够清楚？

### 2.3 产品机会

微信没有向普通工具类小程序开放长期订阅消息，但这反而定义了产品边界：CoDone 不做高频轰炸式提醒，而是做“每件任务、每个接收人、一次明确订阅”的轻提醒。产品价值在于降低邀请和协作成本，而不是承诺无限推送。

## 三、产品定位与目标

### 3.1 一句话定位

**CoDone：把待办放进微信聊天里，和好友一起办完。**

英文品牌：**CoDone**  
中文副标题：**一起把事办完**

### 3.2 目标用户

| 用户类型 | 典型场景 |
|---------|---------|
| 情侣/伴侣 | 家务、采购、旅行准备、纪念日安排 |
| 家人 | 家庭采购、孩子事项、老人就医、节日准备 |
| 好友 | 露营、搬家、聚会、共同出行 |
| 小团队/室友 | 值日、团建、宿舍采购、活动筹备 |

### 3.3 核心价值

- **少一步**：从微信聊天直接进入清单，不要求对方下载 App。
- **看得见**：任务卡、负责人、完成进度在聊天和清单里同步可见。
- **说得清**：谁负责、谁完成、谁还没订阅，一眼能看懂。
- **不打扰**：只在用户主动订阅后发送到期提醒，一次订阅对应一条提醒。

### 3.4 非目标

- 不做通用即时通讯工具。
- 不做企业级项目管理和复杂审批流。
- 不做长期、高频、无需用户操作的自动推送。
- 不在 MVP 中接入服务号模板消息、短信、App Push。
- 不在 MVP 中做支付、商城、会员和广告。

### 3.5 MVP 验证指标

原型和灰度阶段重点观察：

- 收到邀请的用户中，完成“打开卡片 → 加入清单”的比例。
- 加入清单的用户中，完成“订阅提醒”的比例。
- 被指派任务的完成率。
- 创建者对“任务卡 + 进度同步”的满意度。
- 用户对“一次订阅只能提醒一次”的接受度。

本阶段不以日活、收入为优化目标。

## 四、用户与角色

### 4.1 身份

- **微信用户**：通过微信登录获得 `openid`，作为 CoDone 的用户标识。
- **清单创建者**：创建清单的人，拥有成员管理、清单设置和归档权限。
- **协作成员**：通过邀请加入清单的人，默认拥有编辑权限。
- **仅查看成员**：可查看清单和任务，但不能编辑；MVP 可先预留角色，暂不作为默认邀请选项。

### 4.2 权限矩阵

| 操作 | 创建者 | 协作成员 | 仅查看成员 |
|------|--------|---------|-----------|
| 查看清单与任务 | 可以 | 可以 | 可以 |
| 新建/编辑任务 | 可以 | 可以 | 不可以 |
| 删除任务 | 可以 | 仅自己创建的任务 | 不可以 |
| 指派负责人 | 可以 | 可以 | 不可以 |
| 邀请成员 | 可以 | 不可以 | 不可以 |
| 移除成员 | 可以 | 不可以 | 不可以 |
| 修改成员角色 | 可以 | 不可以 | 不可以 |
| 归档清单 | 可以 | 不可以 | 不可以 |
| 退出清单 | 不可以（需先转让或归档） | 可以 | 可以 |
| 订阅自己的提醒 | 可以 | 可以 | 可以 |
| 替他人订阅提醒 | 不可以 | 不可以 | 不可以 |

> 说明：MVP 默认邀请后为“协作成员”；“仅查看成员”作为后续能力，避免首版权限复杂度过高。

## 五、核心使用场景

### 场景 A：个人任务

用户创建“本周要办”清单，添加任务、设置截止时间，自己完成。此时 CoDone 是一个轻量清单工具。

### 场景 B：好友协同

用户创建“周末露营准备”，把“带露营灯”指派给好友林晓，通过微信分享卡片邀请对方。林晓打开卡片加入清单，自己订阅提醒；到期时收到服务通知，点击进入任务并完成。

### 场景 C：群任务

用户在“周末露营群”分享清单，群成员加入后分别负责不同任务。任务卡显示整体进度和成员完成情况；创建者可以主动 @ 未完成成员，但不能定时自动群发。

### 场景 D：到期提醒

任务到期前，已订阅的用户收到一条微信服务通知；通知点击回到任务详情。一次订阅只对应一条提醒，发送后需要重新订阅。

### 场景 E：限制与异常

- 好友没有订阅：到期时没有服务通知，任务详情显示“未订阅”。
- 好友拒绝订阅：不重复弹窗，提供重新订阅入口。
- 一次订阅额度已用完：显示“提醒已发送，再次提醒需重新订阅”。
- 邀请失效：提示发起人重新分享。
- 成员被移出清单：无法继续访问该清单数据。

## 六、产品范围

### 6.1 MVP 必须包含

| 模块 | 范围 |
|------|------|
| 账户 | 微信静默登录、用户身份、头像昵称补充 |
| 清单 | 创建、查看、编辑、归档、成员列表 |
| 任务 | 新建、编辑、指派、截止时间、完成、重新打开 |
| 协同 | 分享卡片邀请、加入确认、成员角色 |
| 提醒 | 一次性订阅消息、到期发送、发送结果记录 |
| 通知 | 微信服务通知跳转、CoDone 内通知中心 |
| 聊天卡 | 单聊/群聊任务卡展示，普通分享卡片可用 |
| 设置 | 提醒状态、成员管理、隐私与帮助 |

### 6.2 MVP 建议包含

- 聊天工具模式的单聊/群聊增强卡（需审核通过；失败时回退普通分享卡）。
- 群任务成员完成状态和手动 @提醒。
- 清单内“待办 / 已完成”筛选。

### 6.3 后续版本

- 重复任务与提前提醒（每次仍需重新订阅）。
- 仅查看成员、成员角色转让。
- 任务评论、附件、图片。
- 模板清单、批量导入。
- 服务号模板消息或其他外部通知通道。
- 多语言和海外版。

### 6.4 明确不做

- 长期订阅消息。
- 未经用户点击的定时群发。
- 读取微信好友列表、自动加好友。
- 替好友订阅或替好友接收通知。
- 公众号模板消息群发。

## 七、信息架构与页面清单

### 7.1 底部导航

- **今日**：跨清单聚合今天/本周要处理的任务。
- **清单**：所有我创建或参与的清单。
- **我**：提醒状态、成员关系、帮助与设置。

### 7.2 页面清单

| 编号 | 页面 | 作用 | 主要入口 |
|------|------|------|---------|
| P1 | 今日 | 聚合待办、今日摘要、快捷完成 | 打开小程序 |
| P2 | 清单 | 浏览和管理所有清单 | 底部 Tab |
| P3 | 清单详情 | 查看清单成员、任务和进度 | 清单卡片 |
| P4 | 任务详情 | 查看任务、订阅提醒、完成/编辑 | 任务行、聊天任务卡、通知 |
| P5 | 新建/编辑任务 | 创建或修改任务 | P1/P3/P4 |
| P6 | 邀请/加入 | 分享清单、好友确认加入 | P3 邀请、分享卡片 |
| P7 | 微信聊天 | 单聊/群聊任务卡、服务通知、@提醒 | P6 分享后 |
| P8 | 通知中心 | CoDone 内提醒与协作动态 | P1 铃铛、P9 |
| P9 | 我的/设置 | 提醒状态、清单关系、帮助 | 底部 Tab |

### 7.3 状态覆盖

所有数据页面需覆盖：

- 默认态
- 空态
- 加载态（骨架屏）
- 错误态（原因 + 重试）
- 无权限/已移出清单
- 邀请失效
- 订阅未开启/已开启/已使用
- 任务待完成/已完成/已过期/已重新打开

## 八、功能需求

### 8.1 账户与身份

**用户故事**：作为微信用户，我希望打开小程序就能开始使用，以便不注册新账号也能创建清单。

**业务规则**

- 使用 `wx.login` 获取临时 `code`，服务端换取 `openid` 并建立会话。
- 不强制填写手机号；头像昵称使用微信头像昵称填写能力或用户主动填写。
- 同一微信用户在不同清单中使用同一 CoDone 用户身份。
- 不在前端暴露 `session_key`。

**验收标准**

- 首次打开小程序不出现独立注册页。
- 登录失败时显示重试，不丢失本地草稿。
- 同一用户再次进入能恢复自己的清单和任务。

### 8.2 清单

**用户故事**：作为创建者，我希望创建一个共享清单并邀请好友，以便把一件事的所有任务放在同一个地方。

**业务规则**

- 清单字段：名称、图标/颜色、创建者、成员、任务数、完成进度、下一次截止时间、状态（进行中/已归档）。
- 清单名称 1～30 个字符；同一用户下可重名，但需在列表中可区分。
- 创建者可以重命名、归档、移除成员、修改成员角色。
- 成员可以退出清单；创建者退出前必须转让或归档（MVP 可限制创建者不能直接退出）。
- MVP 单个清单成员上限建议 20 人。

**验收标准**

- 创建清单后立即可见，且创建者自动成为 owner。
- 成员看到的清单名称、任务和进度与创建者一致。
- 被移出清单的成员再次打开链接时提示无权限。

### 8.3 任务

**用户故事**：作为清单成员，我希望创建任务并指派给某个人，以便明确谁负责什么。

**业务规则**

- 任务字段：标题、所属清单、创建者、负责人、截止时间、重复规则（MVP 只展示“不重复”，重复能力后续开放）、提醒开关、备注、状态、完成人、完成时间。
- 标题 1～60 个字符；截止时间默认为空，可设置为具体日期时间。
- 负责人可以是自己、清单成员或未指定。
- 任一有编辑权限的成员可以完成任务；记录完成人和完成时间。
- 创建者可以重新打开已完成任务。
- 任务列表默认按截止时间升序、无截止时间在后。
- 删除任务仅创建者或清单创建者可操作；MVP 建议使用软删除。

**验收标准**

- 任务创建/编辑后，P1、P3、P7 的进度和状态同步。
- 勾选完成只改变任务状态，不误触进入详情。
- 未指定负责人的任务仍可正常显示和完成。

### 8.4 邀请与加入

**用户故事**：作为创建者，我希望把清单分享到微信好友或群聊，以便对方不用搜索就能加入。

**业务规则**

- 邀请通过微信小程序分享卡片完成，不读取好友列表，不自动加好友。
- 分享卡片携带清单 ID 和邀请令牌；令牌默认 7 天有效。
- 好友打开卡片后看到清单名称、邀请人、成员数、任务数和权限，点击“加入清单”后成为协作成员。
- 创建者可以在分享面板选择“可编辑 / 仅查看”；MVP 默认“可编辑”。
- 邀请失效、清单归档、成员已满时给出明确提示。
- 加入成功后进入清单详情，并提示“开启提醒”。

**验收标准**

- 分享卡片可以在单聊和群聊中打开。
- 加入后成员立刻能看到清单任务。
- 邀请失效不会泄露清单任务内容。

### 8.5 聊天任务卡

**用户故事**：作为好友，我希望在微信聊天里直接看到任务卡和进度，以便不用先打开小程序就知道要做什么。

**业务规则**

- MVP 先支持普通小程序分享卡片；聊天工具模式作为增强能力。
- 聊天工具模式需基础库 3.7.8+、微信 8.0.56+，使用独立分包、Skyline 渲染，分包不超过 500KB。
- 每个小程序只能配置一个聊天工具；需审核，失败时回退普通分享卡。
- 任务卡显示：清单名、任务数、完成进度、负责人头像、截止时间、操作按钮。
- 群任务卡显示成员完成状态和整体进度。
- `wx.notifyGroupMembers` 只能在用户点击时调用，不能定时自动发。
- 不在聊天工具模式内使用普通转发、外跳小程序、广告等被禁能力。

**验收标准**

- 单聊和群聊都能打开任务卡。
- 任务完成后卡片副标题/进度更新。
- 未订阅时不会出现服务通知。

### 8.6 提醒与订阅消息

**用户故事**：作为负责人，我希望任务到期时收到微信服务通知，以便不会忘记。

**业务规则**

- 使用微信小程序订阅消息，不把“服务通知”当作可直接群发的通道。
- 一次性订阅：用户每完成一次订阅，只能下发一条对应模板消息；可不限时间发送。
- 订阅必须由用户在小程序内点击触发；不能静默订阅、不能替他人订阅。
- 长期订阅仅向政务民生、医疗、交通、金融、教育等线下公共服务开放；CoDone 的“工具-效率”类目不适用。
- 用户勾选“总是保持以上选择，不再询问”只代表后续调用不弹窗，不改变“一次订阅一条”的性质。
- MVP 每个任务、每个负责人只设置一个到期提醒；提前提醒、重复提醒放在后续版本。
- 发送前校验订阅额度；发送后记录 `msgid`、发送时间、结果、错误码。
- 发送失败可重试，但必须做幂等，避免同一订阅重复发送。
- 服务通知被用户免打扰、关闭微信通知或系统限制时不保证强提醒。

**验收标准**

- 未订阅用户到期不收到服务通知，任务详情显示“未订阅”。
- 已订阅用户到期收到一条服务通知，点击可进入任务详情。
- 同一订阅发送成功后再次发送被阻止，提示“需重新订阅”。
- 后续支持重复任务时，每次提醒都需要重新订阅。

### 8.7 通知中心

**用户故事**：作为用户，我希望在 CoDone 内看到任务提醒和协作动态，以便集中处理。

**业务规则**

- 通知类型：任务到期提醒、任务完成、被邀请加入清单、成员变更。
- 通知字段：类型、标题、正文、关联任务/清单、创建时间、已读状态。
- 未读数量显示在 P1 铃铛上。
- 点击通知跳转对应页面，并标记已读。
- 通知中心不替代微信服务通知；微信服务通知仍是外部触达通道。

**验收标准**

- 通知列表按时间倒序。
- 点击通知能打开正确任务或清单。
- 空态文案明确，不显示“暂无数据”。

### 8.8 我的 / 设置

**用户故事**：作为用户，我希望查看自己的提醒状态和清单关系，以便知道哪些提醒已开启。

**业务规则**

- 展示头像、昵称、CoDone 副标题。
- 展示“我的清单”及角色。
- 展示微信服务通知状态、已订阅提醒数量、使用说明。
- 提供帮助与反馈、关于 CoDone、隐私政策。
- 不提供主题切换、演示控制、重置数据等非产品功能。

### 8.9 视觉与交互原则

- 品牌统一为 CoDone，副标题“一起把事办完”；不再使用“同办”。
- 视觉方向：iOS 液态玻璃/毛玻璃，半透明层次、柔和环境光、细边框和克制阴影；只做浅色主题，不做深色切换。
- 玻璃只用于顶部导航、清单摘要、任务卡、TabBar、弹层和通知；正文列表保持足够不透明度。
- 主色为 iOS 系统蓝 `#0071E3`；按压或浅底上的强调文字用 `#0057BD`；珊瑚橙 `#FF8A65` 只用于好友任务细线、圆点和头像淡底，不承担小字。
- 系统字体；标题 34px、页面标题 28px、卡片标题 20px、正文 15～16px、辅助文字 12～13px。
- 触控目标不小于 44×44px；正文对比度不低于 4.5:1；玻璃不能模糊到影响阅读。
- 原型只展示一台手机，所有页面和弹层在手机内完成；正式产品不出现演示控制、模拟到期、重置数据等调试入口。
- 动效 0.24s ease，只使用透明度与位移动效，尊重系统减少动态效果设置。

## 九、数据模型

### 9.1 核心实体

| 实体 | 关键字段 |
|------|---------|
| User | id、openid、unionid（可选）、昵称、头像、创建时间 |
| List | id、名称、图标/颜色、owner_id、状态、创建时间、归档时间 |
| ListMember | id、list_id、user_id、role（owner/editor/viewer）、加入时间 |
| Task | id、list_id、title、creator_id、assignee_id、due_at、repeat_rule、status、completed_by、completed_at、note |
| Invite | id、list_id、inviter_id、token、role、expires_at、used_at |
| Subscription | id、user_id、task_id、template_id、status（unused/used/failed）、msgid、sent_at |
| Notification | id、user_id、type、title、body、target_type、target_id、read_at、created_at |

### 9.2 关系

- 一个 User 可以创建多个 List，也可以作为成员加入多个 List。
- 一个 List 有多个 ListMember；owner 唯一。
- 一个 List 有多个 Task；Task 最多一个当前负责人。
- 一个 Task 对每个接收人最多有一条有效订阅记录。
- 一个 Subscription 发送成功后对应一条 Notification。

### 9.3 状态流转

任务状态：

`待完成 → 已完成 → 待完成（重新打开）`

订阅状态：

`未订阅 → 已订阅 → 已使用/发送失败 → 需重新订阅`

清单状态：

`进行中 → 已归档`

## 十、关键流程

### 10.1 创建清单并邀请

1. 用户进入 P2，点击“新建清单”。
2. 填写清单名，创建成功，进入 P3。
3. 创建任务并指派负责人。
4. 点击“邀请”，选择微信好友或群聊。
5. 分享卡片发出，好友打开 P6。
6. 好友点击“加入清单”，成为协作成员。

### 10.2 好友订阅并收到提醒

1. 好友在 P3 打开任务，进入 P4。
2. 查看“未订阅”状态，点击“订阅提醒”。
3. 微信订阅弹窗出现，好友点击“允许”。
4. P4 显示“已订阅 1 次”。
5. 到期时后端发送订阅消息，用户收到服务通知。
6. 点击通知回到 P4，完成任务。
7. P1、P3、P7 的进度同步更新。

### 10.3 群任务

1. 创建者在群聊分享清单。
2. 群成员加入，分别负责不同任务。
3. P7 群任务卡显示成员完成状态。
4. 创建者点击“提醒未完成成员”，触发 `wx.notifyGroupMembers`。
5. 群聊出现 @ 提醒；该操作只在点击时发生。

### 10.4 异常流程

- 订阅被拒绝：P4 显示未订阅，提供“重新订阅”。
- 邀请过期：P6 显示失效，提示重新分享。
- 成员被移出：再次进入显示无权限，不展示任务内容。
- 通知发送失败：记录错误码，P8 显示“发送失败”，允许重新订阅后重试。

## 十一、非功能需求

| 类型 | 要求 |
|------|------|
| 性能 | 首屏在 4G 网络下 2 秒内可交互；列表分页或虚拟滚动；避免一次渲染过多任务 |
| 安全 | 服务端校验清单成员权限；不信任前端传入的 list_id/task_id；敏感密钥只放服务端环境变量 |
| 隐私 | 仅收集完成任务所需信息；提供隐私政策和数据删除入口；不读取通讯录 |
| 兼容性 | 常规小程序基础库；聊天工具模式需 3.7.8+，失败时回退普通模式 |
| 可用性 | 通知发送幂等、失败重试、记录发送结果；避免重复提醒 |
| 可访问性 | 触控区域 ≥44px；正文对比度 ≥4.5:1；文字放大后不截断 |
| 可维护性 | 订阅模板、通知文案、任务状态集中配置；日志可追踪 msgid 和错误码 |

## 十二、依赖与约束

| 依赖/约束 | 说明 |
|----------|------|
| 微信登录 | `wx.login` + 服务端 `code2Session` |
| 微信分享 | `onShareAppMessage`；不能读取好友列表 |
| 微信订阅消息 | `wx.requestSubscribeMessage` + 服务端 `subscribeMessage.send` |
| 服务通知 | 订阅消息进入微信“服务通知”，不是独立推送通道 |
| 聊天工具模式 | Beta；基础库 3.7.8+、微信 8.0.56+；单小程序一个聊天工具；500KB 分包；Skyline |
| 小程序类目 | 建议“工具-效率”；个人主体可用，但聊天工具模式审核需实测 |
| 模板 | 需确认公共模板库是否有“待办提醒/任务提醒”；没有则申请，审核结果不确定 |
| 后端 | 云开发或自建服务；定时触发器、订阅记录、通知日志 |
| 服务号模板消息 | 不纳入 MVP；作为后续可选通道，不作为绕过订阅规则的手段 |

## 十三、验收标准

### 13.1 功能验收

- [ ] 微信登录成功，用户能恢复自己的清单。
- [ ] 创建清单、任务、指派负责人、设置截止时间可用。
- [ ] 分享卡片可发给好友/群聊，好友可加入。
- [ ] 成员权限符合权限矩阵。
- [ ] 任务完成后，P1、P3、P7 同步更新。
- [ ] 未订阅用户不会收到服务通知。
- [ ] 已订阅用户收到一条服务通知，点击进入正确任务。
- [ ] 同一订阅不能重复发送；再次提醒需重新订阅。
- [ ] 邀请失效、成员被移出、订阅拒绝均有明确提示。
- [ ] 通知中心可查看、已读、跳转。

### 13.2 体验验收

- [ ] 首次进入不要求注册账号。
- [ ] 从聊天卡片到任务详情不超过 3 步。
- [ ] 订阅状态和提醒限制在任务详情中一眼可见。
- [ ] 空态/加载/错误态文案具体，有下一步操作。
- [ ] 390px 宽无横向滚动；触控目标 ≥44px。
- [ ] 关键操作有即时反馈，不使用 alert。

### 13.3 合规验收

- [ ] 小程序备案、隐私保护指引、用户数据删除入口完成。
- [ ] 不出现“微信官方”“微信待办”等误导性名称。
- [ ] 不读取通讯录、不自动加好友、不代用户订阅。
- [ ] 任务内容、昵称头像等用户数据有明确的存储和删除策略。
