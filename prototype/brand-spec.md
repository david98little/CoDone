# CoDone · 视觉规范

**一句话系统**：在雾蓝、淡紫、暖杏的低饱和环境光里，用一台深色金属边框的 iPhone 承载克制的液态玻璃分层；系统蓝（Apple 蓝）只负责进度与主操作，珊瑚橙只负责好友任务的细线。

## 六个核心 Token

| Token | 源值 | OKLch | 角色 |
| --- | --- | --- | --- |
| `--bg` | `#EEF3F8` | `oklch(96.1% 0.010 240)` | 页面环境底色 |
| `--surface` | `#FFFFFF` | `oklch(100% 0 0)` | 任务列表、卡面白底 |
| `--fg` | `#0B1220` | `oklch(18.3% 0.031 263)` | 主文字、状态栏 |
| `--muted` | `rgb(11 18 32 / .62)` | `oklch(53.0% 0.015 265)` | 次要文字、时间、标签 |
| `--border` | `rgb(11 18 32 / .08)` | `oklch(94.4% 0.004 245)` | 分隔线、描边 |
| `--accent` | `#0071E3` | `oklch(56.3% 0.193 256)` | 进度、主按钮、选中态 |
| `--accent-deep` | `#0057BD` | `oklch(46.5% 0.168 256)` | 按压填充、浅底上的强调文字 |

补充语义色：珊瑚橙 `#FF8A65` / `oklch(75.5% 0.151 38.3)` 仅用于好友任务 2px 细线与圆点；错误色 `#D92D20` / `oklch(57.6% 0.209 29.5)` 预留，不在主流程出现。珊瑚橙作为 15px 以下文字不达标，因此只做图形强调，不承担文字。

## 字体

单一系统字体栈，与 iOS / 微信小程序一致：

- UI / 标题 / 正文：`-apple-system, BlinkMacSystemFont, "SF Pro Display", "PingFang SC", "Microsoft YaHei", sans-serif`
- 数字：同一字体栈 + `font-variant-numeric: tabular-nums`，保证进度、时间、通知不跳动。
- 层级靠字重与字距区分：主问候 34/700，页面标题 28/700，卡片标题 20/600，正文 15–16/400，辅助 12/500。

## 观察到的视觉规则

1. 玻璃只出现在指定的六类层级：小程序导航、共享清单摘要、聊天任务卡、TabBar、底部弹层、服务通知；任务列表用 86% 白色实底，不叠加重度模糊。
2. 玻璃统一为 1px 半透明白描边 + 顶部内高光 + 柔和外阴影，不使用发光、厚描边或大面积反光。
3. 系统蓝（`#0071E3`，iOS 系统蓝同族）是唯一功能强调色；白字置于其上 4.7:1。作小字落在白底或淡蓝底时改用 `#0057BD`（`--accent-deep`），保证 ≥4.5:1；珊瑚橙只以 2px 线、6px 圆点和头像淡底出现，不做文字色。
4. 圆角阶梯：普通卡片 20–24，底部弹层 32，胶囊 999；所有可点击热区 ≥44×44。
5. 间距以 8 为基准，主要使用 8 / 12 / 16 / 24 / 32；只做浅色主题，不做深色切换。
